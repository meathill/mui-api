2026 年 6 月 9 日、Anthropic は Claude Fable 5 を公開した。これは新しい Mythos クラスの frontier system から、初めて一般に利用可能になったモデルだ。Flagship launch としては位置づけが珍しい。Fable 5 は、はるかに高性能なモデルを一般利用向けに安全化したバージョンとして説明されている。最も強力な variant は、多くの人が直接使えるものではない。

AI に関心のある人にとって、これは問いを組み替える。もはや「frontier はどれほど高性能か」だけではない。「その frontier のどこまでを安全に公開できるのか、そして公開できない部分を vendor はどう扱うのか」だ。Fable 5 は Anthropic の答えであり、guardrails は後付けではなく product の中に組み込まれている。

## Anthropic が実際に公開したもの

Anthropic の [Claude Fable 5 and Claude Mythos 5 発表](https://www.anthropic.com/news/claude-fable-5-mythos-5)によれば、この launch は同じ基盤モデル上に構築された二つの tier で構成されている。

- **Claude Fable 5** は公開版で、enterprise 顧客と有料 subscriber が利用でき、一般利用向けに安全化されている。
- **Claude Mythos 5** は同じモデルだが、一部領域で safeguards が解除されたものだ。Project Glasswing を通じて、少数の cyberdefenders と infrastructure provider にのみ提供される。

Anthropic は、Mythos 5 が世界中のどのモデルよりも強い cybersecurity capability を持つとしている。この一文だけで二段構造の理由は分かる。完全版は、Anthropic が全員には渡さないと判断するほど強力であり、Fable 5 はその能力を責任ある形で一般ユーザーへ届ける方法なのだ。

Fable 5 はすでに [Amazon Bedrock](https://aws.amazon.com/blogs/aws/anthropic-claude-fable-5-on-aws-mythos-class-capabilities-with-built-in-safeguards-now-available/) でも利用できるため、cloud team は Anthropic と別個に契約しなくてもアクセスできる。

## 重要な能力変化

見出しになるべきなのは単一の benchmark ではない。Frontier reasoning、より強い coding、そして組み込み safety が同時に動いていることだ。

| 領域 | Anthropic が強調した点 | なぜ重要か |
| --- | --- | --- |
| Agentic coding | Cognition の FrontierCode 評価で frontier model の中で最高スコア | 複数ステップの実装、debugging、長期的な engineering work により合う |
| Token efficiency | 過去の Claude モデルより token 効率が高い | token 単価が上がっても、完了タスクあたりの実コストは下がりうる |
| Cybersecurity | Mythos クラスの能力、全モデル中最強（Mythos 5 の背後に gate） | 公開 tier が open access ではなく active misuse controls 付きで出る理由 |
| Safety routing | 高リスク request を検出し redirect する classifiers | 後付けではなく、モデルの一部としての guardrails を備えた frontier capability |

Token efficiency の点は、最初に見える以上に重要だ。Fable 5 は Claude Opus 4.8 より token 単価が高い。しかし同じ仕事をより少ない token で終えられるなら、請求に効くのは完了タスクあたりのコストだ。

## Safety: classifiers と Opus 4.8 fallback

最も興味深い engineering detail は、Fable 5 が単純な拒否に頼らず安全性を保つ方法だ。Anthropic は潜在的な misuse を監視する新しい classifiers を追加した。Request が cybersecurity、biology and chemistry、model distillation といった sensitive area に触れると、classifier が intercept し、response は Fable 5 ではなく Claude Opus 4.8 によって自動的に処理される。

つまり safety layer はただ block するだけではない。必要な少数の request について、より制約の強いモデルへ graceful に degrade する。Anthropic によれば、初期データでは Fable session の 95% 以上が fallback をまったく伴わない。日常的な作業では、完全な Fable 5 と話していることになる。

これは意味のある design pattern だ。モデルが長い horizon で行動する能力を高めるほど、その周囲の controls も強くならなければならない。Risky request をより安全なモデルへ route するのは、一律拒否より使いやすい答えであり、この launch で最も研究する価値のある部分だ。

## 計画しておくべき価格

Anthropic は Fable 5 を Claude Opus 4.8 のおよそ 2 倍に価格設定している。

| モデル | Input | Output |
| --- | ---: | ---: |
| `claude-fable-5` | $10 / 1M tokens | $50 / 1M tokens |
| `claude-opus-4-8` | $5 / 1M tokens | $25 / 1M tokens |

Anthropic 標準の prompt caching は適用されるため、繰り返し context は cache read で大きく割引され、cache write では一度だけ premium がかかる。見出し価格の正しい読み方は、token efficiency の主張と並べて見ることだ。token 単価が高いからといって、完了タスクあたりのコストが自動的に高くなるわけではない。仮定を hard-code する前に、自分の billing dashboard で実際の数字を確認してほしい。

## Availability

現時点で Fable 5 は paid と enterprise 向けの release だ。

- Enterprise 顧客と有料 subscriber が利用可能。
- AWS 経由で利用したい team 向けに Amazon Bedrock でも利用可能。
- Mythos 5 は Project Glasswing を通じて少数の cyberdefenders と infrastructure provider に制限されており、general release には含まれない。

## 開発者にとっての意味

Fable 5 は frontier model の行き先を示している。最大能力は、そのどこまでを一般ユーザーに届けるかを決める controls と、ますます強く結びつく。これはモデル評価の仕方を変える。

- 孤立した prompt ではなく、本当に重要な workflow をテストする。
- graceful な safety behavior を想定し、hard refusal ではなく稀な fallback に備えて設計する。
- token 単価ではなく完了タスクあたりのコストを測り、token efficiency が数字に出るようにする。
- どの workload が本当に frontier model を必要とし、どれが安い tier で十分かを追跡する。

## MuiRouter ユーザーにとっての意味

MuiRouter は単純な考え方で作られている。一つの API key、一つの integration pattern、主要 AI model へのアクセスをより明確に route する方法だ。Fable 5 のような二段 launch は、unified gateway の価値が出る典型的な場面である。

私たちは `claude-fable-5` を MuiRouter catalog に追加し、Anthropic の公開料金に沿って pricing した。アプリケーション側の integration は変わらない。モデルと価格は gateway の背後で設定される。モデルが独自の routing と safety behavior を持って出てくるとき、ecosystem が動く中で自分の integration を安定させておく価値は大きい。

明確にしておくと、実際の routing は依然として upstream availability に依存する。`claude-fable-5` は、自分の環境で end-to-end に確認してから live として扱ってほしい。だがこれはまさに、stable unified integration が効く launch だ。モデル環境の変化が速いほど、その churn を application code に届かせたくない。

## まとめ

Claude Fable 5 が注目に値するのは、一つの benchmark というより、その ship のされ方だ。Frontier-class model が built-in safety routing とともに公開され、最も強力な形は Mythos 5 の背後に gate されている。際立つのは classifier + fallback の design であり、日常体験を速く保ちながら、最も risky な request をより制約の強いモデルへ送る。

AI で開発しているなら、今テストする価値がある。評価ケースとコスト期待値を準備し、実際の workload で safety routing がどう振る舞うかを観察し、integration を安定させておく。そうすれば次の frontier model は rewrite ではなく configuration change になる。
