2026 年 7 月 9 日、OpenAI は GPT-5.6 ファミリーを ChatGPT、Codex、OpenAI API 向けに一般提供（GA）しました。6 月 26 日から始まった限定プレビューを経て、本格ロールアウトが進んでいます。新フラッグシップが **Sol**、日常向けのバランス層が **Terra**、同系列で最も安い選択肢が **Luna** です。

Anthropic が Fable を出したあと、米政府が AI サービスへの世界的な利用条件を引き締めたため、OpenAI は GPT-5.6 をまず少数ユーザーに開放し、問題ないと判断してから全世界に広げる必要がありました。Fable のパンチを受け止められるかへの期待はかなりありましたが、コミュニティの反応を見る限り、今のところそれは難しそうです。主に高くなり、5.5 より効率がはっきり上がったとは言えません。

## OpenAI が実際に出したもの

OpenAI の [GPT-5.6 公式発表](https://openai.com/index/gpt-5-6/) によると、7 月 9 日に ChatGPT、Codex、API が同時に立ち上がり、おおよそ 24 時間かけて世界中への展開が進みます。

命名は意図的です。

| 階層 | 役割 | 公式リスト価格（1M tokens あたり） |
| --- | --- | ---: |
| **Sol** | フラッグシップの知能とコーディング | 入力 $5 / 出力 $30 |
| **Terra** | 日常のバランス型。GPT-5.5 に競争力がありつつ低コスト — 以前の mini に近い位置 | 入力 $2.50 / 出力 $15 |
| **Luna** | ファミリー最速・最安 — 以前の nano に近い位置 | 入力 $1 / 出力 $6 |

数字（`5.6`）が世代を示し、Sol / Terra / Luna はそれぞれ独自のペースで進化できる能力階層です。API 上の明示的な model ID は `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna` です。短い `gpt-5.6` は Sol と同等です。Terra や Luna が欲しいときはフル ID を使ってください。

## このリリースが違う理由

OpenAI は GPT-5.6 を **デフォルトは効率的、必要時に最大性能** と位置づけています。以下は公式の言い分です。

| 領域 | OpenAI が強調した点 | なぜ重要か |
| --- | --- | --- |
| Token 効率 | より少ない token・より低い推定コストで強い結果 | 完了タスクあたりのコストが単価より良く見えることがある |
| コーディングエージェント | Artificial Analysis Coding Agent Index、Terminal-Bench 2.1、DeepSWE などで SOTA 主張 | 多段実装、CLI ワークフロー、長期エンジニアリングに適合 |
| ナレッジワーク | BrowseComp と OSWorld 2.0 が強化。資料・文書・表がより安定 | 散らかった入力から納品物への道がより確実 |
| デザイン + computer use | コード吐き出しだけでなく、描画後 UI を検査・ refinement | 仕事を戻せる協働者に近い |
| Programmatic Tool Calling | ツールを協調する軽量プログラムを書いて実行できる | 往復回数と中間 token の膨張を抑える |
| `max` / `ultra` | より長い推論時間（`max`）。デフォルトで multi-agent 並列（`ultra`） | タスクが正当化するときだけ増額する |

パートナーも同じ調子で並びました。品質が上がり、しばしば token も latency も下がる、という話です。商売上の相互賛美として参考にする程度にして、自分で試してください。

## 可用性と API の詳細

この製品ラインでは GPT-5.6 が初めて **ChatGPT、Codex、API を同日** に届けました（その前に短い trusted partner プレビューがありました）。

- **ChatGPT / ChatGPT Work / Codex：** Sol / Terra / Luna はプランごとにロールアウト。Free と Go は Plus / Pro / Business / Enterprise より限定的なセットになることが多いです。コミュニティのチャットでは、まだ 5.6 が見えないという声もあります。
- **API：** 3 階層とも呼び出し可能。Responses API の Programmatic Tool Calling は Zero Data Retention（ZDR）互換と明記。multi-agent は ultra 相当の協調を beta で開始。
- **Prompt caching：** GPT-5.6 以降、cache write は **1.25 倍** のレート、cache read は引き続き **9 割引き**（1 割価格）。prompt caching を使うには明示的な cache breakpoint と最低 30 分の cache 寿命が必要です。

本番前は、アカウントのモデル選択と [API 料金ページ](https://openai.com/api/pricing/) を信じてください。第三者の context 長をハードコードしないでください。多くのリストは Sol/Terra を約 1M context と書いていますが、自分のダッシュボードが確認するまではヒント扱いです。

## 言いづらい安全性

OpenAI は、red teaming、大規模自動テスト、プレビュー中のパートナー圧測を含むより長い評価のあと、これまでで最も堅牢なセーフガードとともに GPT-5.6 を投入したと述べています。モデルに仕事を「やらせる」期待が大きいほど、制御は重要です。閲覧・コード編集・ソフトウェア操作ができる agent に繋ぐとき、特にそうです。

あいにく今日すでに X では、Codex がユーザーのホームディレクトリを全部消した、という苦情が出ていました……

## ビルダーにとっての意味

GPT-5.6 は業界を「賢いチャット」から **仕事を終わらせるオペレーター** へさらに進めます。実務の問いがこうなります。

- どの階層をどの仕事に：難しい agentic 仕事は Sol、日常の既定は Terra、量とコストが支配するなら Luna？
- コストを「完了した workflow の値段」として評価しているか、token 単価だけ見ていないか？
- 単一 agent の `max` ではなく、いつ `ultra` に割増を払う価値があるか？
- モデル名と階層が動き続けるなかで、安定した統合をどう保つか？

最後の一点こそ、統合ゲートウェイが価値を出すところです。

## MuiRouter ユーザーにとっての意味

MuiRouter の目標は単純です。API キーは 1 つ、リクエスト形は 1 つ、いま最良のモデルに届くこと。OpenAI が公式に出した以上、これらの新モデルも試し始められます。

## まとめ

GPT-5.6 が注目に値するのは、OpenAI が **タスクを終わらせるコストであって、token 単価ではない** と明示しているからです。ChatGPT や Codex を使うなら、長い agentic・コーディング仕事にまず Sol を試し、日常の文案なら Terra が妥当な第一階層です。Luna については、個人的には下位層に寄せるのはおすすめしません。

初期のコミュニティ反応を見る限り、5.5 からの伸びは劇的ではないかもしれず、Fable にも届きません。当面は日常的な knowledge base の更新くらいに捉えておくのがよいでしょう。
